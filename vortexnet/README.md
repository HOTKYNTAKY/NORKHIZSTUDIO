# نصب فروشگاه VORTEXNET روی Ubuntu 22.04

این پوشه از فایل پیوست `vortexnet-setup-v30.sh` استخراج شده و مستقل از سایت خبری ریشهٔ مخزن است. نصاب برای یک سرور اختصاصی Ubuntu 22.04 و دامنهٔ **www.vortexnett.shop** طراحی شده است؛ سایت خبری مخزن را نصب نمی‌کند. پیش از استفاده روی سروری که سایت دیگری دارد، از تنظیمات Nginx و داده‌ها بکاپ بگیرید و تداخل دامنه، پورت‌های ۸۰، ۴۴۳ و ۹۲۷۳ و سرویس‌های موجود را بررسی کنید. نصاب سرویس‌ها و تنظیمات سیستم را تغییر می‌دهد.

## پیش‌نیازها

1. در پنل DNS دامنه، رکورد `A` برای `www` را به `176.97.218.219` تنظیم کنید. تنظیم DNS در اختیار شرکت ثبت‌کننده/ارائه‌دهندهٔ DNS است و این نصاب بدون دسترسی به آن نمی‌تواند رکورد را بسازد. رکوردهای `A` اضافی یا `AAAA` نادرست را حذف یا اصلاح کنید؛ اگر از CDN/پروکسی استفاده می‌کنید، برای نصب اولیه آن را غیرفعال کنید. انتشار DNS ممکن است زمان ببرد.
2. این IP باید واقعاً به سرور مقصد تعلق داشته باشد. ورودی TCP پورت‌های ۸۰ و ۴۴۳ را در فایروال سرور و پنل ارائه‌دهنده باز کنید. پورت SSH فعلی را نبندید. نیازی به بازکردن ۹۲۷۳ نیست.
3. دسترسی root یا sudo، اینترنت برای مخازن Ubuntu، NodeSource، npm و Let's Encrypt و دسترسی ورودی Let's Encrypt به پورت ۸۰ لازم است. در ایران دسترسی به برخی از این سرویس‌ها ممکن است محدود باشد؛ در صورت خطا دسترسی شبکه را برطرف و نصاب را دوباره اجرا کنید.
4. کل این مخزن را روی سرور کپی یا clone کنید (فقط کپی کردن فایل نصاب کافی نیست). از شاخه‌ای استفاده کنید که پوشهٔ `vortexnet` را دارد.

## نصب

بستهٔ فشرده را روی سرور بارگذاری و باز کنید (`tar -xzf vortexnet-ubuntu22.tar.gz`)، یا کل مخزن را کپی کنید. سپس از داخل پوشه‌ای که پوشهٔ `vortexnet` در آن قرار دارد اجرا کنید:

```bash
sudo SSL_EMAIL=you@example.com bash vortexnet/install-ubuntu22.sh
```

به جای ایمیل نمونه، ایمیل واقعی را وارد کنید تا اخطارهای انقضای گواهی ارسال شوند. نصاب دو بار رمز مدیر را به‌صورت مخفی می‌پرسد (حداقل ۱۰ کاراکتر)، وابستگی‌ها را نصب می‌کند، سایت را می‌سازد، سرویس systemd و Nginx را تنظیم می‌کند و گواهی Let's Encrypt می‌گیرد. اگر `SSL_EMAIL` مشخص نشود، بدون ایمیل ثبت می‌شود و اخطار انقضا دریافت نخواهید کرد.

برای نصب بدون تعامل، رمز را در فایلی خصوصی روی خود سرور قرار دهید و مسیر آن را با `ADMIN_PASSWORD_FILE` بدهید (رمز را در فرمان، تاریخچهٔ shell یا چت قرار ندهید):

```bash
sudo chmod 600 /root/vortexnet-admin-password
sudo SSL_EMAIL=you@example.com ADMIN_PASSWORD_FILE=/root/vortexnet-admin-password bash vortexnet/install-ubuntu22.sh
sudo rm /root/vortexnet-admin-password
```

- سایت: https://www.vortexnett.shop/
- مدیریت: https://www.vortexnett.shop/admin
- API فقط روی `127.0.0.1:9273` گوش می‌دهد و از Nginx عبور می‌کند. پورت مستقیم پنل قدیمی را باز نکنید.
- در تنظیمات پنل، **شماره کارت و نام دارنده را بررسی و اصلاح کنید**؛ در نصب تازه کارت ۶۲۱۹۸۶۱۴۹۵۶۱۶۹۲۱ به نام ایمان دهقانی پیش‌فرض است؛ در به‌روزرسانی مقدار ذخیره‌شده حفظ می‌شود مگر با گزینهٔ `VORTEXNET_APPLY_PAYMENT_CARD=1` که این کارت را اعمال می‌کند. سپس آدرس و مشخصات پاسارگارد را تنظیم و قبل از پذیرش سفارش تست کنید.

تا صدور موفق گواهی، پیکربندی اولیه فقط چالش ACME را ارائه می‌کند و سایت را با HTTP عمومی نمی‌کند. اگر صدور گواهی شکست بخورد، نصب خطا می‌دهد؛ پس از اصلاح DNS یا دسترسی شبکه، همان فرمان را دوباره اجرا کنید. تایمر `certbot.timer` تمدید را بررسی می‌کند و پس از تمدید، Nginx reload می‌شود. برای تست تمدید: `sudo certbot renew --dry-run`.

## انتقال داده از سرور قبلی

پیوست شامل کاربران، سفارش‌ها، رمز مدیر و کلیدهای پاسارگارد نیست. برای انتقال آنها، سایت قدیمی را در زمان مهاجرت متوقف کنید تا داده‌ها هنگام کپی تغییر نکنند، سپس پوشهٔ `server/data` نسخهٔ قدیمی را **از مسیر امن و خصوصی** به `/opt/vortexnet/server/data` در سرور جدید منتقل کنید. آن را در Git، لینک عمومی یا چت قرار ندهید. فایل‌ها شامل اطلاعات حساس و نشست‌ها هستند. نمونه روی سرور قدیم، با جایگزینی مسیر واقعی:

```bash
sudo systemctl stop norkhiz-api
sudo tar -C /PATH/TO/OLD/APP/server -czf /root/vortexnet-data.tar.gz data
```

آرشیو را با `scp` به سرور جدید منتقل کنید. فقط آرشیوی را باز کنید که خودتان ساخته و به آن اعتماد دارید. روی سرور جدید، قبل از نصب اول:

```bash
sudo install -d -m 700 /opt/vortexnet/server
sudo tar -xzf /root/vortexnet-data.tar.gz -C /opt/vortexnet/server --no-same-owner --no-same-permissions
sudo rm /root/vortexnet-data.tar.gz
sudo SSL_EMAIL=you@example.com bash vortexnet/install-ubuntu22.sh
```

رمز مدیر و داده‌های موجود حفظ می‌شوند. در صورت داشتن سرور قدیمی، پس از بررسی کامل نسخهٔ جدید و DNS، سرویس قدیمی را خاموش نگه دارید تا سفارش‌ها بین دو نسخه جدا نشوند. فایل `server/.env` قدیمی در این نصب استفاده نمی‌شود. به‌روزرسانی با اجرای دوبارهٔ همان فرمان از نسخهٔ جدید کد انجام می‌شود و پوشهٔ داده حذف نمی‌شود؛ پیش از هر به‌روزرسانی بکاپ خصوصی بگیرید.

## عیب‌یابی

```bash
sudo systemctl status vortexnet nginx certbot.timer
sudo journalctl -u vortexnet -n 100 --no-pager
sudo nginx -t
sudo certbot certificates
```

کد فروشگاه از پیوست بازیابی شده و بازبینی امنیتی جامع یا تست واقعی صدور گواهی/اتصال پاسارگارد روی سرور مقصد انجام نشده است. قبل از استفادهٔ تجاری، امنیت، پشتیبان‌گیری و عملکرد پرداخت را بررسی کنید.

## خرید بدون ثبت‌نام و سرویس تست

این نسخه به‌جای نام کاربری و رمز، یک شناسهٔ تصادفی و محرمانه در کوکی امن مرورگر نگه می‌دارد. سفارش‌ها، چت و سرویس‌ها به همان مرورگر متصل‌اند. با پاک‌شدن کوکی، انقضای آن یا تغییر مرورگر/دستگاه، دسترسی به این سابقه خودکار منتقل نمی‌شود. مشتری باید کد سفارش، چهار رقم آخر کارت و لینک اشتراک خود را در جای امن نگه دارد؛ پیگیری سفارش خریداری‌شده با کد و چهار رقم کارت همچنان موجود است.

برای مشتری قدیمی، فقط نشست موجود و معتبر در همان مرورگر حفظ می‌شود؛ ورود و بازیابی حساب قدیمی در نسخهٔ جدید غیرفعال‌اند. اگر نشست قدیمی منقضی شده باشد، سابقهٔ قبلی به دستگاه جدید متصل نمی‌شود. پیش از به‌روزرسانی، از داده‌ها بکاپ بگیرید و به مشتریان قبلی اطلاع دهید.

تست به‌صورت پیش‌فرض خاموش است. در پنل مدیریت ← تنظیمات فروشگاه ← سرویس تست، پنل فعال و دارای اتصال، حجم بر حسب گیگ (مثلاً ۰٫۵) و مدت بر حسب ساعت را انتخاب کنید و تست را فعال و ذخیره کنید. مشتری از صفحهٔ خرید، تست را دریافت می‌کند؛ لینک در «سرویس من» نشان داده می‌شود. هر مرورگر یک تست می‌گیرد و تمدید رایگان مدت تست غیرفعال است. کوکی شناسهٔ واقعی سخت‌افزار نیست: با پاک کردن کوکی یا مرورگر دیگر می‌توان محدودیت یک تست را دور زد؛ محدودیت IP صرفاً تعداد درخواست‌ها را محدود می‌کند و جلوگیری قطعی از سوءاستفاده نیست.

آزمایش خودکار با پنل شبیه‌سازی‌شده: `node --test vortexnet/tests/device-trial.test.mjs`. اتصال به پنل پاسارگارد واقعی و عملکرد مرورگر سرور مقصد باید جداگانه بررسی شوند.


## انتخاب پنل و لوکیشن

پنل‌های فعال و دارای آدرس و اعتبارنامه در ابتدای صفحهٔ خرید نشان داده می‌شوند. پس از تنظیم پنل‌ها، در مدیریت ← پنل‌های پاسارگارد از دکمهٔ «بررسی و ذخیره گروه‌های همه پنل‌های فعال» استفاده کنید؛ نتیجهٔ اتصال و تعداد گروه‌ها برای هر پنل جدا گزارش می‌شود. پیش از تأیید، نام و محتوای گروه‌ها را در خود پاسارگارد بررسی کنید: گروه الزاماً لوکیشن نیست و هر نامی که منتشر شود برای عموم قابل مشاهده است. گروه‌های محدودشده به شناسه‌های مجاز پنل فیلتر می‌شوند. تغییر آدرس پنل یا فهرست شناسه‌های مجاز، فهرست منتشرشده را پاک می‌کند و دریافت دوباره لازم است.

اگر فهرست تأییدشده‌ای نباشد، لوکیشن نامعلوم نمایش داده می‌شود و سفارش مثل نسخهٔ قبل با گروه‌های مجاز پنل ساخته می‌شود. اگر فهرست وجود داشته باشد، مشتری گروه را انتخاب می‌کند و در تأیید سفارش فقط شناسهٔ همان گروه برای ساخت کاربر فرستاده می‌شود. تغییرات بعدی گروه‌ها در پاسارگارد خودکار به‌روز نمی‌شود؛ بعد از هر تغییر فهرست را دوباره بررسی و دریافت کنید. وجود گروه یا موفقیت خواندن آن ثابت نمی‌کند سرور مربوطه واقعاً در دسترس است یا کشور آن صحیح است. تست رایگان از تنظیمات اختصاصی خودش استفاده می‌کند و انتخاب لوکیشن خرید را تغییر نمی‌دهد.

## انتقال اشتراک توسط مشتری به پنل دیگر

در «سرویس من» مشتری می‌تواند پنل فعال مقصد و در صورت وجود گروه منتشرشده، گروه مقصد را انتخاب کند. پیش از انتقال هشدار روی صفحه و تأیید صریح لازم است؛ پیامک تلفنی ارسال نمی‌شود. انتقال به پنل گران‌تر هم رایگان و با همان حجم باقیمانده است. سرویس مبدأ ابتدا متوقف می‌شود؛ حجم باقیمانده بر اساس مصرف زنده‌ای که پاسارگارد گزارش می‌کند و timestamp انقضای فعلی خوانده می‌شود. سرویس مقصد ساخته و بررسی می‌شود، سپس مبدأ از پنل حذف و لینک جدید به مشتری داده می‌شود. اشتراک قبلی و لینک آن بازگشت خودکار ندارند.

فقط سرویس فعال با حجم محدود، مصرف و انقضای معتبر و دو پنل متفاوت قابل انتقال است. مجوزهای لازم در پاسارگارد شامل خواندن و تغییر و حذف کاربر مبدأ، خواندن گروه‌ها و خواندن و ایجاد کاربر مقصد است؛ در صورت نیاز به اصلاح مصرف، تغییر کاربر مقصد هم لازم است. در زمان انتقال هر دو پنل باید قابل دسترس باشند. این عملیات در سفارش ذخیره می‌شود؛ در قطع ارتباط ممکن است سرویس موقتاً متوقف بماند. مشتری دکمهٔ «ادامه انتقال» دارد و مدیر نیز در کارت سفارش نیمه‌تمام دکمهٔ ادامه دارد. پیش از هر دخالت دستی، وضعیت هر دو پنل و مرحله ذخیره‌شده را بررسی کنید و اشتراک‌ها را خودسرانه فعال، حذف یا دوباره ایجاد نکنید. ورود بکاپ در زمان انتقال در حال انجام مسدود است.

آمار پاسارگارد یا نودها ممکن است با تأخیر گزارش شود؛ بنابراین تطبیق حجم به آخرین مصرفی که پنل هنگام انتقال گزارش می‌کند وابسته است و دقت مصرفی که دیرتر برسد تضمین نمی‌شود. قبل از فعال‌کردن برای مشتریان، روی هر ترکیب پنل واقعی با یک اشتراک آزمایشی و دسترسی‌های واقعی، توقف، مصرف و حذف مبدأ، لینک مقصد و زمان انقضا را جداگانه بررسی کنید. تست‌های `node --test vortexnet/tests/*.test.mjs` از دو پنل شبیه‌سازی‌شده استفاده می‌کنند و جایگزین تست واقعی نیستند. انتقال قدیمی دستی مدیر جداگانه عمل می‌کند و همچنان ممکن است به‌جای حذف مبدأ، صرفاً آن را غیرفعال کند.

هنگام به‌روزرسانی فروشگاه، اگر نصب قبلی GAVIDCHAT وجود داشته باشد، نصب‌کننده مسیر آن را در nginx حفظ می‌کند.

### انتخاب گروه‌های هر پنل در مدیریت

در مدیریت ← «پنل‌های پاسارگارد»، روی «تنظیم گروه‌ها / ویرایش» پنل مورد نظر بزنید. فهرست گروه‌ها از همان پنل خوانده می‌شود؛ در صورت نیاز دکمهٔ «دریافت گروه‌ها از این پنل» را بزنید. با تیک‌ها می‌توانید یک یا چند گروه را انتخاب کنید و سپس «ذخیره پنل» را بزنید. انتخاب «همه گروه‌ها» شامل گروه‌هایی است که بعداً به پنل اضافه می‌شوند؛ انتخاب «فقط گروه‌های تیک‌خورده» باید حداقل یک گروه داشته باشد. اگر اتصال ناموفق باشد، انتخاب ذخیره‌شده پاک نمی‌شود و شناسه‌ها را می‌توان دستی وارد کرد.

این تنظیم گروه سرویس‌های قبلی را تغییر نمی‌دهد. برای سرویس جدید اگر مشتری در صفحهٔ خرید گروه منتشرشده‌ای را انتخاب کند، همان گروه از میان گروه‌های مجاز به سرویس داده می‌شود؛ در غیر این صورت مجموعهٔ گروه‌های مجاز به پاسارگارد فرستاده می‌شود. تغییر فهرست شناسه‌های مجاز، فهرست گروه‌های منتشرشده برای مشتری را پاک می‌کند؛ اگر نام‌ها را پس از بررسی مناسب نمایش عمومی می‌دانید، دوباره از دکمهٔ دریافت و انتشار گروه‌ها در مدیریت استفاده کنید. نام گروه پاسارگارد لزوماً نشان‌دهندهٔ لوکیشن جغرافیایی نیست.
